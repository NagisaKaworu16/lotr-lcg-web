# 已确认的项目决定

## D001 · 独立项目

魔戒 LCG 与用户的移动应用、开发者账户及消耗工作分开组织，避免串入无关记忆。

## D002 · 按阶段制作和验收

优先自动计算和规则校验，玩家保留战术选择。每次开放新阶段，验证后停在该阶段末。当前到第六阶段，不把旧手动辅助流程当作后续自动规则。

## D003 · 原版基础规则口径

以原版基础规则及官方 FAQ 1.9 为核心，依据卡牌原文显式实现，不从中文摘要自动推断能力。不含新版战役／噩梦模式。旅行窗口在旅行框架步骤之后；当前对旅行费用翻牌的厄运、涌现及空牌库处理，按 phase4-acceptance.md 中列出的原版规则口径执行。若更改口径，须先找原始依据并记录测试变化。

## D004 · 两层方案确认

派遣先提交暂定名单，再全员二次确认。普通行动事件／能力先进入暂定清单，确认前不执行。调整后清除对应全队二次确认，避免旧确认误用于新方案。程序按规则顺序执行，可为响应暂停。

## D005 · 信息与回退

暂定动作可撤销；已抽牌、查看牌库或揭示遭遇的信息无法收回。同机整桌撤销是纠错辅助。未来联机必须用服务器状态版本、玩家身份和确认记录，不能把当前本地 history 直接作为多人同步方案。

## D006 · 直接打开离线包

保留 index.html 加 assets 的使用方式，不要求用户安装 npm。源代码与生成页面同步提交，测试验证离线构建。实际连线图片的可用性独立验收。

## D007 · 从现有事实建立 Git 历史

现有工作目录此前没有 Git。第一次提交是 v0.9.0 快照，不伪造 v0.7.x／v0.8.x 的 Git 历史。旧版本只在发行包与 CHANGELOG 的历史记录中追溯。GitHub目标需先核对，不能把独立新历史直接强推覆盖已有远端。

## D008 · 私有仓库上传授权与历史整合

2026-10-19，用户明确同意将当前项目代码和73张基础卡图上传到私有仓库 NagisaKaworu16/lotr-lcg-web。使用独立分支 codex/project-memory-v090 与草稿PR，保留 main 及原始资料，不自动合并或公开仓库。远端导入继承原 main 历史，本地旧独立快照单独归档。

## D009 · 第五阶段按原版时序

原版规则书第16–17、31页：主动交战（每人至多1名、不受交战值限制）→玩家行动→交战检定→玩家行动。检定按起始玩家顺序循环，每次取不超过该玩家威胁的最高交战值；同值由起始玩家选择。没有普通行动插入检定循环。全队二次确认是执行前交流缓冲，不改变正式交战顺序。安都因127仅跳过检定，不跳过主动交战。强制效果优先并暂停继续执行，森林蜘蛛每次交战的加成持续整回合并叠加。

## D010 · 第六阶段确认与信息边界

敌人顺序、防御名单、玩家攻击先暂定再全队确认；响应和已揭示暗影即时处理，不塞入普通行动暂定区。暗影按玩家顺序和敌人交战值分配，同值先确定顺序；缺牌不重洗。允许在攻防步骤之间使用行动，暗影逐张取消和结算。共同防御合计防御值，但全部伤害给同一名防御者；无人防御只选己方一名英雄。角色离场即从当前及挂起攻击名单移除，重新入场不会恢复参与。插入座狼骑手用虚拟攻击者，实体仍为原暗影牌，不增加实体卡数量。第六阶段结束后停住验收。

## v0.12.0 刷新与回合结束分离

刷新的重置、威胁、先手轮换先全员确认，再按框架一次执行；蛛网选择仅暂存，不提前扣资源。普通行动在框架之后开放。阶段结束延迟效果完成后才截取回合结束触发，避免潜行攻击返回的甘道夫又被弃掉。已触发目标效果保存原目标，不因同一时点另一效果使来源脱离而撤销。新回合入口与资源收集分开，防止重复抽牌；每回合能力次数在进入下一回合后才清空。

## D011 · 智能窗口保留规则自动化（v0.13.0）

用户确认保持网页版自动化核心，不采用让玩家自行判断全部时点的TTS模式。将「空窗口让过」与「执行实际操作的确认」分开：合法性仍复用规则引擎；无可用普通行动才自动推进，或由全队明确继续当前窗口。卡牌普通行动可按本阶段忽略提醒，条件变化重新检查，新来源不继承旧实例的忽略设置。响应、强制选择、攻防和投入方案均保持独立。旧存档无设置保留详细模式，新对局默认智能；渲染不改变规则状态。


## D012 · 卡牌桌面与集中操作（v0.14.0）

用户要求结合BGA操作逻辑与诡镇网页版桌面择优改版。采用中央公共桌面、下方当前玩家、右侧流程与日志；固定操作栏说明当前任务，卡牌直接选取替代投入和攻防名单弹窗。复用原有纯前端规则引擎，不引入BGA服务器框架。界面草稿不写存档或历史；提交仍由引擎重新验证，正式效果保持全队确认。预览仅注明基础数值，特殊能力与暗影以正式结算为准。复杂目标与费用保留原选择框，避免为外观重写规则。
